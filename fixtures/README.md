# 测试样本

> **这些全部是脚本生成的合成数据，不含任何真实的公司文件、客户信息或财务数据。**
> 里面的公司名、合同编号、金额、人名都是编的，仅用于验证解析与检索是否正确。
> 用 `python fixtures/generate.py <输出目录>` 可以随时原样重建。

`多模态测试样本/` 里的 7 个文件各测**一个具体的失败模式**，不是随手造几个 PDF。

| 文件 | 考什么 | 关键事实（用来核对它有没有编） |
|---|---|---|
| `01-扫描件-采购合同.pdf` | 中文 OCR 基本盘 | 编号 `PRJ-2026-0817`、金额 `1,187,432.00`、到期 `2026年2月1日`、续约需提前 `60 天` |
| `02-扫描件-预算表格.pdf` | 图像化**表格结构还原** | 研发部 `1,200,000 / 1,187,432 / -1.0%`；市场部 `+6.9%`；合计 `2,142,972` |
| `03-扫描件-英文发票.pdf` | 非中文场景 + 数字对账 | `INV-2026-0042`、三项明细合计 `1,187,432.00`、`Net 30` |
| `04-扫描件-手写签批.pdf` | 手写体 + 印章，OCR 难度最高 | Falcon → Phoenix 更名、生效 `2026年1月22日`、要求更新 `runbook` |
| `05-扫描件-两页合订.pdf` | 多页逐页转写 + **页码定位** | 第 1 页合同，第 2 页预算表 |
| `06-图片-预算表.png` | 图片格式本身能否进索引 | 内容同 02 |
| `07-对照组-有文本层.pdf` | **视觉解析不该被触发** | 标记词 `TEXTLAYER-CONTROL-9931` |

## 第 7 个是关键

它有真正的文本层。**只测正例不算测过** —— 那样分不清「视觉能力有效」
和「什么都往视觉模型上送」。后者会让成本失控：每页一次模型调用，
一份 200 页的扫描件能烧掉几十万 token。

本机实测：

| 文件 | 用了视觉 | 耗时 |
|---|---|---|
| 01 ~ 06 | 是 | 4.3 ~ 16.6s |
| **07 对照组** | **否** | **0.0s** |

逐条核对，**全部准确转写，零错误**。
